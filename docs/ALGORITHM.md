# 算法说明（skintone-serve）

> 本文只讲**技术事实**：用了什么公式、什么算法、测得准不准、哪里测不准。
> 所有阈值与常量的唯一出处是 `skintone/config.py`，本文引用其名字而不复制数值（少数关键数值为便于阅读直接写出，如与代码不符以代码为准）。

色彩学约定见 `CONTRACT.md` §4：白点 D65、CIE 1931 2° 观察者、sRGB 传递函数按 IEC 61966-2-1、一切平均与最小二乘在**线性空间**做、色差一律 CIEDE2000、色适应一律 Bradford。

---

## 0. 三条路线与它们各自能证明什么

| 路线 | 输入依赖 | 能自证的部分 | 不能自证的部分 |
|---|---|---|---|
| A 有卡 `card` | 打印的 `skintone-a4-v1` | 逐块 ΔE00 残差 → `ccm_delta_e` 门禁 | 纸本身印得对不对（需 §2.4 自标定） |
| B 无卡 `nocard` | 巩膜 / 牙齿 / 背景 + 用户光源先验 | 投影残差 Duv；ROI 质量门禁 | **没有**标定残差，故置信度上限被硬性压到 `medium` |
| C 光照不变量 | 与 A/B 同一张图的另一路计算 | 色相对比、对数色度分解 | 只有相对量，不能单独出绝对值 |

置信度不是"精度评分"，而是**这次测量有多少可自证的证据**。分数低于 `CONFIDENCE_LOW_MIN` 时服务端返回 `advice: null` 并给出"该怎么做"，这是设计目标而不是降级行为。

## 1. 色彩学基础（`skintone/color/srgb.py`）

### 1.1 sRGB 传递函数（IEC 61966-2-1）

```
线性化：  c <= 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4
反线性化：l <= 0.0031308 ? 12.92 * l : 1.055 * l ** (1/2.4) - 0.055
```

**为什么必须在线性空间做平均**：编码域不是线性域。取 `0` 与 `1` 两个编码值的算术平均得到 `0.5`，而在线性域取平均再编码得到约 `0.735`。在人像里这意味着系统性地偏暗偏饱和。`tests/test_color_srgb.py::test_averaging_linear_is_not_averaging_encoded` 把这条钉住了。

### 1.2 线性 sRGB ↔ CIE XYZ（D65）

```
XYZ = M @ linearRGB,   M = [[0.4124564, 0.3575761, 0.1804375],
                            [0.2126729, 0.7151522, 0.0721750],
                            [0.0193339, 0.1191920, 0.9503041]]
```

### 1.3 CIELAB

白点 `(Xn, Yn, Zn) = (0.95047, 1.0, 1.08883)`。

```
f(t) = t > (6/29)^3 ? cbrt(t) : (t * (29/3)^3 + 16) / 116
L* = 116 f(Y/Yn) - 16
a* = 500 (f(X/Xn) - f(Y/Yn))
b* = 200 (f(Y/Yn) - f(Z/Zn))
C* = hypot(a*, b*)
h_ab = atan2(b*, a*) 转角度后取 [0, 360)
```

### 1.4 CIEDE2000（`skintone/color/ciede2000.py`）

按 Sharma、Wu、Dalal (2005) 的原始公式实现，包含 `G` 彩度压缩、`T` 色相权重、`Δθ`/`R_C` 旋转项与 `S_L, S_C, S_H` 权重。

**硬门禁**：`tests/test_ciede2000.py` 内置官方 `ciede2000testdata.txt` 的 34 组测试向量，逐组要求 `abs=1e-4` 一致。这 34 组是专门用来暴露实现 bug 的（色相在 0°/180° 附近翻转、`C'` 趋零、大色差等），不过就没有"色差可信"这回事。

## 2. 色适应（`skintone/color/adaptation.py`）

Bradford 为默认（与 ICC v4 及主流色彩管线一致，便于和其它工具对照）：

```
M_BFD = [[ 0.8951,  0.2664, -0.1614],
         [-0.7502,  1.7135,  0.0367],
         [ 0.0389, -0.0685,  1.0296]]
CAT = M^-1 @ diag((M @ white_dst) / (M @ white_src)) @ M
```

同时提供 von Kries（Hunt-Pointer-Estevez 基）与纯 XYZ 对角缩放，供交叉检查。响应里的 `illuminant.adaptation` 永远显式声明用的是哪一个。

## 3. 光源估计（`skintone/color/illuminant.py` + `skintone/vision/roi.py` + `skintone/vision/face.py`）

### 3.1 为什么不做全图 gray-world

契约 §0 第 1 条。人脸特写里皮肤常常占画面 30%–60%，且皮肤本身是暖色；gray-world 会把这个暖色当成光源色偏给"中和"掉，**恰好抹掉要测的信号**。所以本服务里不存在任何对全图做 gray-world 的代码路径；光源候选一律先经过语义遮罩。

### 3.2 候选来源与遮罩

| 来源 | 选择规则 | 权重 |
|---|---|---|
| 巩膜 | Haar 眼部检测 → 眼框中心 35% → 选 HSV 饱和度最低的像素（契约 §5B 的原文规则） | 1.0 |
| 牙齿 | Haar 微笑级联定位嘴部，失败则取脸上 62%–92% 高度、28%–72% 宽度的带状区 → 取**最亮**的低饱和像素的前 25% | 0.9 |
| 背景非彩色区 | 画面外框 8% 带内、排除皮肤/人脸/色卡后，取饱和度最低的 25%，且饱和度仍须低于上限 | 0.6 |

遮罩由 `vision/face.py::face_mask`（人脸框外扩 15%）与 ROI 多边形合并而成。候选不足 `ILLUMINANT_MIN_CANDIDATE_PIXELS` 的来源直接丢弃；全部丢弃时退回 D65 并在响应里标记 `assumedD65: true`。

**背景带为什么用"最低饱和 25%"而不是绝对阈值**：真正中性的墙面在钨丝灯下拍出来**本来就是有色的**（例如 HSV 饱和度 0.2 左右）。只用一个绝对阈值会把每一张暖光室内照片全部否掉。相对分位数 + 一个足够宽松的绝对上限，才能既接受"中性面 + 有色光"，又拒绝"本身就是彩色的背景"。

### 3.3 CCT 与一维化

1. **McCamy 近似**只用来给搜索定个起点：
   `n = (x - 0.3320) / (0.1858 - y)`，`CCT = 449n³ + 3525n² + 6823.3n + 5520.33`
   注意：McCamy 只在 A 光源（2856 K）与 D65（6504 K）附近真正精确到 2 K 以内，别的地方误差可达数百 K——所以它**只是种子**。
2. **普朗克轨迹**：`planck_xyz(T)` 直接用普朗克定律积分 CIE 1931 2° 观察者。
   CIE 匹配函数没有内嵌 81 行数表，而是用 Wyman–Sloan–Shirley (JCGT 2013) 的**多瓣分段高斯解析拟合**，1 nm 步长积分。这是有意的取舍：省掉一张大表，代价是色度约 0.001 量级偏差（2856 K 处实测 `(0.4464, 0.4085)`，公开值 `(0.4476, 0.4074)`）。
3. **CIE 日光轨迹**：`D_T` 的官方闭式（4000–7000 K 与 7000–25000 K 两段），6504 K 处精确复现 `(0.31271, 0.32902)`。
4. **投影**：把估计色度转到 CIE 1960 UCS `uv`，在轨迹上做最近点搜索（粗网格 + 三分细化），得到 `(CCT, Duv)`。`Duv` 带符号：**正值 = 轨迹上方（偏绿），负值 = 下方（偏品红）**。
   轨迹选择：用户的 `illuminantGuess` 是把日光/阴影指向日光轨迹、把钨丝/荧光/LED 指向普朗克轨迹；`unknown` 时两条都算，取 `|Duv|` 更小的那条。
5. **一维校正**：把估计投影到轨迹上，等于把二维自由估计压成"只有一个未知量 CCT"。最终光源色度 = 该轨迹在最终 CCT 处的点。
6. **用户先验融合**：在 **mired**（`1e6 / T`）域按 `ILLUMINANT_PRIOR_WEIGHT = 0.25` 混合。用 mired 是因为它是沿轨迹的感知均匀轴，直接对开尔文做加权平均是错的。权重刻意低于 0.5：先验只微调不确定的估计，不该压过一个真实测量值。

### 3.4 已知局限（认真读这一段）

- **巩膜不是白体**。它略带黄、且常处于眼窝阴影里。用它的中位数当光源，本身就带偏差。
- **牙齿会被唇色与阴影污染**，而且很多人拍照不露齿——这条来源经常直接缺席。
- **背景不一定中性**。灰墙、白墙可以，木地板、绿色植物不行；后者会被绝对饱和度上限挡掉（这是有意的保守）。
- **相机白平衡是最大的敌人**。手机默认自动白平衡会把光源色偏消掉一部分，再交给我们就已经晚了。这就是为什么 `capture.wbLocked` 出现在契约里，也是为什么 `wbLocked=false` 时响应会给出警告。
- **`Duv` 小不代表光源估对了**，只代表"这个估计落在物理可能的轨迹上"。`illuminant_residual` 是自洽性检查，不是准确度证明。

## 4. ROI 与鲁棒统计（`skintone/vision/roi.py`）

1. 客户端传原图像素坐标闭合多边形 → `cv2.fillPoly` 生成并集掩膜。
2. **截断剔除**：任一通道编码值 ≥ 250 或 ≤ 5 的像素占比记为门禁 `clipping` 的实测值。
3. **高光剔除**：CIELAB `L* > 85` 的像素占比记为 `specular`。
4. 剩余像素在**线性空间**取逐通道**中位数**作为该 ROI 的颜色；同时计算截尾均值（每端裁 `ROI_TRIM_FRACTION = 10%`）供诊断。
5. **离散度**：对每个有效像素算它与 ROI 中位色的 CIEDE2000，取这些值的中位数，作为门禁 `roi_dispersion`。

用中位数而不是均值的原因很直接：一块反光、一根头发、一颗痣都能把均值拖走，而中位数不会。`tests/test_roi.py::test_outliers_do_not_move_the_median` 用"25% 的 ROI 全白"验证了这一点。

**注意**：`cv2.fillPoly` 会把多边形的两条边线都画上，所以 `w × h` 的方块实际覆盖 `(w+1) × (h+1)` 像素。门禁用的是比例和计数，不受这一格影响。

## 5. 色卡路线（`skintone/vision/card.py`）

### 5.1 定位与矫正

1. `cv2.aruco` + `DICT_4X4_50` 找 id 0/1/2/3 四个标记。`cv2.aruco` 返回的角点顺序固定为 TL、TR、BR、BL（标记自身正立方向），因此可以按下标与规格里的角点一一配对。
2. 16 个角点 → `cv2.findHomography` → `cv2.warpPerspective` 到规范光栅 `2480 × 3508`（A4 @ 300 DPI，`CARD_PX_PER_MM = 11.809523…`）。
3. 四个标记缺一不可（契约 §2.3 的 `CARD_NOT_DETECTED` 就是这么定义的）。

这一步把"斜着拍"变成"正着看"，并把后续所有几何都变成与拍摄角度无关的常量查表。

### 5.2 采样

每块取中心 **60%**（`PATCH_SAMPLE_FRACTION`）区域，在**线性空间**取逐通道中位数。取中位数而不是均值是为了避开印刷网点、灰尘和边缘串色（双线性重采样会把相邻色块糊到边缘几个像素上）。

任何通道中位数 ≥ `CCM_DROP_SATURATED_SRGB8 = 250` 的色块被标记为不可用并剔除——过曝色块的颜色是未知的，放进最小二乘只会污染解。这就是为什么纯白块 `W`（#FFFFFF）在真实拍摄里**本来就应该**被剔除。

### 5.3 CCM 最小二乘

```
M = XYZ_ref @ pinv(RGB_meas)                     # 3x3
M = XYZ_ref @ pinv([RGB_meas; 1])                # 3x4，带偏移
```

- 输入 `RGB_meas` 是**线性** sRGB（0–1），`XYZ_ref` 是各色块名义 sRGB 值对应的 D65 XYZ。
- 3x4 形式多一个常数项，用于补偿相机抬高的黑电平。
- 选择规则（常量驱动）：读黑块 `K`（名义 #000000）实测线性值，若超过 `CCM_OFFSET_BLACK_LEVEL = 0.010` 就用 3x4，否则用条件数更好的 3x3。响应里的 `calibration.ccmKind` 说明用了哪个。
- 最少需要 `CCM_MIN_PATCHES = 12` 个可用色块，否则报错而不是硬解。

**为什么 R/G/B/C/M/Y 不能删**：最小二乘解的质量取决于色块在色彩空间里张成的体积。只有肤色块时 `pinv` 的条件数极差，解在外推到肤色区会把误差放大。契约 §3 专门写了这条。

### 5.4 残差与门禁

逐块算 `ΔE00(名义值, CCM 校正后值)`，均值即门禁 `ccm_delta_e` 的实测值，阈值 5.0。同时返回 `deltaE00Max` 与逐块明细。

### 5.5 卡上光源估计

把可用的中性块（`kind == "gray"`、未过曝、线性均值 > 0.05）的实测线性值取平均，转 XYZ → xy，得到"这张卡当前看到的光"。再走 §3.3 的一维投影。注意：如果相机已经自动白平衡过，这一项会接近 D65——响应里的 `assumedD65` 与 `method` 说明了这次的来源。

### 5.6 自标定（`POST /v1/card/{id}/calibrate`）

用户在自己日光下拍一张卡，反推**这张纸实际印出来的颜色**：

1. 采样所有色块。
2. 取可用中性块，算各自的色度比 `measured / sum(measured)`，取中位数得到纸的色偏 `paper_tint`；白平衡增益 `wb = (1/3) / paper_tint`。
3. 在最亮的中性块上定一个全局亮度增益，使它的亮度等于名义值。**只能有一个全局增益**，因为整体曝光不可知——这就是响应里那句 note 的意思。
4. `grayNeutrality.maxAbsChroma` = 归一化后各中性块的 `C*` 最大值，阈值 `CALIBRATION_GRAY_MAX_CHROMA = 6.0`。
5. `quality.deltaE00MeanAfter`：在 `[0.70, 1.40]` 内再搜一个全局亮度增益，取使逐块平均 ΔE00 最小的那个，报告该最小值。≤ 3.0 为 `good`，≤ 6.0 为 `fair`，否则 `poor`。

得到的 `{patch_id: [r,g,b]}` 存进 SQLite，之后 `POST /v1/analyze` 带 `cardProfileId` 时，这些实测值会**替换名义值**作为 CCM 的参考，从而消掉纸张与打印机的偏色。档案不存在时按契约报 `CARD_PROFILE_NOT_FOUND`。

**自标定的能力上限**：它只能恢复**相对**颜色。一个整体性的亮度缩放、以及拍摄时环境光本身的色度，都是不可观测的。别把它当成把手机变成分光测色仪的东西。

## 6. 肤色描述（`skintone/color/skin.py`）

### 6.1 深浅：ITA（可靠）

```
ITA = atan((L* - 50) / b*) 转角度
```

分档（下界含、上界不含）：

| 类 | ITA° |
|---|---|
| `very-light` | > 55 |
| `light` | 41 ~ 55 |
| `intermediate` | 28 ~ 41 |
| `tan` | 10 ~ 28 |
| `brown` | -30 ~ 10 |
| `dark` | ≤ -30 |

这是皮肤科用了三十年的标准量，是本项目**唯一**敢说"可靠"的轴。它主要吃 `L*` 与 `b*`，对光照强度有一定的内在鲁棒性（`L*` 与 `b*` 同向缩放时比值变化有限）。

### 6.2 冷暖：经验判定（不可靠，真的）

轴向：

```
axis = tanh((h_ab - 48°) / 12°)        # +1 = 暖，-1 = 冷
```

标签按 `axis` 分档：`>= 0.70` warm，`>= 0.30` neutral-warm，`>= -0.30` neutral，`>= -0.70` neutral-cool，否则 cool。橄榄调是独立规则：`h_ab` 高、`a*/b*` 低、`C*` 低三者同时成立时覆盖为 `olive`。

`probabilities` 是对 `{cool, neutral, warm, olive}` 四个声明原型的距离做 softmax 得到的**启发式类别权重**，不是标定过的后验概率。响应里同时给出原始的 `axis.aOverB` 与 `axis.hueAngleDeg`，方便调用方不认同标签时自己判断。

**老实说的局限**：

- **冷暖判定与人类专家的一致率大约只有 75%–85%**，而且这个区间本身没有统一口径——不同研究、不同专家之间的一致率都不同。这不是本实现的谦辞，是这个任务的固有难度：`h_ab` 里混着黑色素、血红蛋白、光照与相机色彩矩阵，四者不可分离。
- **深肤色上冷暖几乎不可判**。深肤色的 `h_ab` 普遍偏高，本规则会把其中很大一部分判成 warm。想看深肤色的底色，请用色卡路线，并且要知道即便如此它仍然是三者中最弱的轴。
- **橄榄调是最不可靠的一档**。"橄榄"在口语里指好几种不同的色相/明度组合，本规则只是把它定义成上面那条数值条件，和你或你的造型师说的"橄榄"可能不是一回事。
- **不要用这个标签做购买决策**。响应里 `confidence.level != "high"` 时，标签的可信度进一步下降。

### 6.3 表面状态与色素分解

- `specular_ratio`：ROI 内 `L* > 85` 的占比。
- `clipping_ratio`：任一通道 ≥250 或 ≤5 的占比。

对数色度（光学密度）分解：

```
OD = -ln(clip(linear, OD_LINEAR_FLOOR, 1))
melaninIndex    = <OD, e_m> / OD_MELANIN_REFERENCE      # e_m = (1, 0, 0)
hemoglobinIndex = <OD, e_h> / OD_HEMOGLOBIN_REFERENCE   # e_h = (-1, 1, 0)/sqrt(2)
```

两个方向在 OD 空间里正交，因此分解数值稳定。

- `e_m` = 红波段密度。黑色素吸收宽且单调（Jacques 2013 给出约 `λ^-3.48` 的消光幂律），而含氧血红蛋白在 610 nm 附近几乎透明，所以红波段是最干净的黑色素读数。
- `e_h` = 绿波段相对红波段的超出量，即皮肤科常用的**红斑指数**（erythema index）形式。含氧血红蛋白的 Q 吸收带在 542/577 nm，正好落在绿通道。

两者都被归一化到 0–1，且截断处清零（色素密度不可能为负）。

**局限**：只有三个宽波段时，黑色素与血红蛋白在色度上是高度相关的。这两个指数是**方向性指标**，不是浓度。它们对阴影与高光的敏感度远低于原始 RGB（这正是它们存在的理由），但把 `melaninIndex` 当成"黑色素含量百分比"是错的。

## 7. 置信度合成（`skintone/analysis.py`）

门禁清单与阈值（契约 §5）：

| id | 阈值 | 类型 | 含义 |
|---|---|---|---|
| `ccm_delta_e` | ≤ 5.0 | max | 色卡标定残差（仅 card） |
| `clipping` | ≤ 0.02 | max | 截断像素占比 |
| `specular` | ≤ 0.08 | max | 高光像素占比 |
| `roi_area` | ≥ 4000 | min | 剔除后有效皮肤像素数 |
| `roi_dispersion` | ≤ 8.0 | max | ROI 内 Lab 色差离散度 |
| `illuminant_residual` | ≤ 0.02 | max | 光源投影残差 \|Duv\|（仅 nocard） |

### 7.1 单门禁满足度

max 型：

```
full_mark = 0.40 * threshold
sat = clamp((threshold - value) / (threshold - full_mark), 0, 1)
```

min 型：`sat = clamp(value / threshold, 0, 1)`。

即"阈值四折以内算满分，线性衰减到阈值处归零"。用曲线而不是 0/1 硬判，是为了让"刚好卡在门禁上"和"差得离谱"在分数上分得开。

### 7.2 合成与封顶

```
score = Σ(w_i · sat_i) / Σ(w_i)          # 权重见 config.GATE_WEIGHTS，默认等权
level = high   if score >= 0.75
        medium if score >= 0.50
        low    if score >= 0.25
        insufficient  otherwise
```

随后施加**语义封顶**（这些是刻意的产品决策，不是数值巧合）：

| 条件 | 封顶 | 理由 |
|---|---|---|
| `roi_area` 不通过 | `insufficient` | 像素都不够，任何数字都是噪声 |
| `ccm_delta_e` 不通过（card） | `low` | 标定本身不可信，不能报 high |
| `illuminant_residual` 不通过（nocard） | `low` | 契约 §5B 的 `ILLUMINANT_UNRELIABLE` |
| 模式上限：`nocard` | `medium` | **无卡路线没有可自证的标定残差**（契约 §9.4） |

最后一条特别说明：无卡模式即使所有门禁都满分，`score` 会算出 1.0，但 `level` 仍被压到 `medium`。这不是保守，而是诚实——那些门禁衡量的都是"这次测量干不干净"，没有一条能证明"颜色是对的"。想拿到 `high`，请用色卡。

### 7.3 拒绝给结论

`level == "insufficient"` 时：

- `advice` 为 `null`（契约 §2.3 硬要求）；
- `warnings` 里给出具体的下一步动作；
- `skin` 里能测的字段照常返回，测不出的字段为 `null`。

**宁可说"测不准，请去做物理试色"，也不要输出一个看起来很精确的数字**——这是本项目的核心设计选择，不是失败路径。

## 8. 配色建议（`skintone/color/palette.py`）

全部由 §6 的实测值按可解释规则生成，**不使用**四季色彩理论之类无据可依的标签。

**推荐色**（6 条，全部满足）：

- 色相偏移 `|Δh| ∈ [25°, 60°]`，正负两个方向都取；
- 彩度比 `C*_target / C*_skin ∈ [0.8, 1.6]`；
- 明度按 `ADVICE_LIGHTNESS_DELTA_TARGETS = (-30, -16, +16, +30)` 形成目标对比；
- Lab → sRGB 越界时**只降彩度**（保明度与色相）二分回 sRGB 立方体内，所以推荐色一定能在屏幕上显示，且色相关系（这正是规则依赖的东西）不变。

**避雷色**：

- 与肤色色相差 < 15° 且彩度显著更高 → 显脏；
- 与该肤色的明度几乎相同且彩度极低 → 显灰；
- 低彩度深色贴近肤色明度 → 显黯淡。

每条 `avoid` 都带上触发它的数值规则文本，便于核对。

**对比度**：有 `hairLStar` 时用 `|L*_hair - L*_skin|`，切点 45 / 25；没有时退化为肤色单轴估计，并在 `warnings` 里明说这是退化估计。

## 9. 精度现状汇总（不吹）

| 项 | 现状 |
|---|---|
| CIEDE2000 | 通过 Sharma 官方 34 组向量，`abs=1e-4` |
| 合成图色卡路线 | 已知真值还原 `ΔE00 ≈ 0.5`（含 4200 K 光照偏移 + 传感器噪声 + JPEG q92）。这是**上界**，不是真实拍摄的表现 |
| 真实拍摄色卡路线 | 取决于打印质量、纸张光泽、是否过曝。`ccm_delta_e` 门禁就是用来在当场告诉你这次准不准的 |
| 无卡路线 | 合成场景 `ΔE00 ≈ 3`；真实场景会明显更差，因为巩膜/牙齿/背景都比合成图里"不那么白" |
| ITA 深浅 | 可靠，与皮肤科标准同源 |
| 冷暖判定 | **与专家一致率约 75%–85%**，深肤色更差 |
| 橄榄判定 | 最弱的一档，只是"高色相 + 低 a/b + 低彩度"的数值定义 |
| 黑色素/血红素指数 | 方向性指标；三通道下两者高度相关，不可当浓度读 |
| 绝对色度 | 无参考物时**不可能**做到绝对精确。整体曝光不可观测、相机色彩矩阵未知、自动白平衡会消掉信号 |

设计立场：**测不准的时候拒绝给结论**，把不确定性以 `confidence.gates` 的实测数值暴露出来，让调用方自己决定要不要信。
